# 1.3 某电商公司正在考虑两种方案来处理售后退款申请：

```
方案 A（`Workflow`）：设计一套固定流程，例如：

A.1 对于一般商品且在 7 天之内，金额 `< 100RMB` 自动通过；`100-500RMB` 由客服审核；`>500RMB` 需主管审批；而特殊商品（如定制品）一律拒绝退款

A.2 对于超过 7 天的商品，无论金额，只能由客服审核或主管审批；

方案 B（`Agent`）：搭建一个智能体系统，让它理解退款政策、分析用户历史行为、评估商品状况，并自主决策是否批准退款
```

请分析：

## 1.3.1 这两种方案各自的优缺点是什么？

### 方案 A (workflow)

#### 优点

- 开发成本低, 系统设计难度低, 技术不复杂, 易实现.
- 执行流程明确可控, 约束清晰, 保证执行结果的确定性.

#### 缺点

- 人工效率低, 如遇复杂状况, 在业务高峰期将成为提效瓶颈, 影响用户体验.
- 灵活性差, 不能高效处理复杂情况, 不能灵活处理边界情况.

### 方案 B (Agent)

#### 优点

- 效率高, 处理灵活, 综合分析复杂信息输入, 能给出更优的解决方案, 人性化服务用户.
- 智能体可学习和进化, 根据环境反馈, 发现更多潜在规律和问题, 迭代优化自身决策, 提升服务质量.



#### 缺点

- 智能体不一定很好理解业务, 逻辑推理任务表现不佳, 决策质量不稳定, 流程不可靠, 可能产生幻觉影响用户体验.
- 可解释性差, 黑盒决策过程面对监管和用户质询难以解释.
- 开发成本高, 技术复杂, 初期效果不稳定, 中间和后期调优需要多方支持, 依赖业务数据严重, 训练数据质量决定智能体上限.



## 1.3.2 在什么情况下 `Workflow` 更合适？什么情况下 `Agent` 更有优势？如果你是该电商公司的负责人，你更倾向于采用哪种方案？
### 分情况讨论:
- 业务初期规模小, 用户少, 规则不复杂, 置信度高, 适合`Workflow`方案.
- 业务高峰期, 场景复杂多变, 用户业务量大, 显式规则难以覆盖全部业务场景, 适合`Agent`方案.

作为电商公司负责人, 我优选后者, Agent在复杂业务高峰期能快速处理用户的多数诉求, 降本增效.

## 1.3.3 是否存在一个方案 C，能够结合两种方案，达到扬长避短的效果？

可充分结合`Workflow`和`Agent`两者优势, 协同工作:
- Workflow快速处理明确简单规则的业务场景, 面对用户的多数简单需求, 工作效率高.
- Agent面向少数业务复杂的边缘情况, 能深度思考和灵活处理, 给出合适解决方案, 解决争议大和风险高的案例.
