# 3.2 Transformer架构是现代大语言模型的基础。

## 3.2.1 自注意力机制（Self‑Attention）的核心思想是什么？

核心思想：模型处理序列里的每一个词时，让序列内部全部单词互相计算语义关联度。针对当前位置的词，计算序列中其余所有词对它的**注意力权重**，权重大小代表语义影响强弱；再对全部词的特征做加权求和，得到该位置新的表征向量。

它可以直接建模全局上下文，无论词语相隔多远都能建立依赖关系，不需要按顺序逐个遍历序列。

## 3.2.2 为什么Transformer能够并行处理序列，而RNN必须串行处理？位置编码（Positional Encoding）在其中起什么作用？

1. **RNN必须串行的原因**

RNN依靠循环连接，当前时刻隐藏状态 h_t = f(h_{t-1},x_t)，**当前时间步的计算必须等待上一个时间步的隐藏状态计算完成**，时间步之间存在强依赖，只能逐个处理token，无法并行。

2. **Transformer可以并行的原因**

Transformer彻底抛弃循环递归结构。自注意力层中，序列所有位置的词向量可以同时输入计算，各个位置的输出互不依赖，不需要等待前一个位置的结果，整个序列可以一次性完成注意力与前馈网络运算，实现并行计算。

3. **位置编码的作用**

Transformer没有循环结构，模型本身无法感知词语先后顺序，打乱词语顺序输入会得到相似的计算结果。
位置编码把位置序号转化为向量，叠加到词嵌入向量上，向模型注入**语序和位置信息**，让模型区分不同位置的token，理解句子顺序语义。

## 3.2.3 Decoder‑Only架构与完整的Encoder‑Decoder架构有什么区别？为什么现在主流的大语言模型都采用Decoder‑Only架构？


### 架构区别

- **完整Encoder‑Decoder架构**：分为编码器Encoder和解码器Decoder两个独立模块。Encoder负责编码源输入序列；Decoder读取Encoder输出的上下文表示，结合掩码自注意力生成目标序列。多用于机器翻译这类输入、输出属于不同序列的任务，依赖成对平行数据。
- **Decoder‑Only架构**：完全舍弃Encoder模块，仅保留带掩码自注意力的Decoder部分。输入输出共用一套模型与词表，采用自回归模式：根据上文预测下一个token。


### 主流大模型选用Decoder‑Only的原因

1. **训练目标统一**：统一使用“预测下一个token”的自回归预训练目标，不需要区分源序列与目标序列，可以直接使用海量无标注单文本进行预训练。
2. **结构简单，易于扩展**：只保留单一解码器模块，不用维护两套子结构；模型扩参、扩展上下文窗口工程实现更简单。
3. **天然适配各类生成任务**：对话、文本续写、代码生成等任务都是自回归生成模式；经过微调后，也可以完成文本理解类任务。
4. **语料获取成本低**：不需要翻译任务所需的成对平行语料，互联网海量原始文本就可以用于预训练，数据资源更加充足。
