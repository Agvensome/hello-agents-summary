### 实验任务：影评情感分析

测试样本包含正向影评、负向影评、中性样本、褒贬混合样本。
实验组包含：贪婪搜索、高温采样、中等温度、低温采样、极低温度、Top‑p、Top‑K多组调参。

#### 各采样参数行为与实验现象

1. **贪婪搜索（**`do_sample=False`**）**

- 行为：解码每一步直接选择概率最高的token，关闭随机采样，输出完全确定、可复现。
- 现象：输出确定性强，适合分类类任务；不存在多样性输出。

2. **高温采样** `temperature=1.5`

- 行为：温度升高，token概率分布被拉平，低概率token被选中概率提升，增强生成多样性。
- 现象：容易出现逻辑错误、情感判断错误；Base基座模型该问题会更加突出。

3. **中等温度** `temperature=0.7`

- 行为：平衡随机性与生成质量，是通用文本生成的常用参数。
- 现象：具备适度多样性，出错概率介于高温与低温之间。

4. **低温采样** `temperature=0.3`

- 行为：放大高概率token权重，抑制低概率候选，降低随机性，输出保守稳定。
- 现象：情感分类任务正确率高，效果接近贪婪搜索。

5. **极低温度** `temperature=0.1`

- 行为：几乎消除随机性，输出高度保守。
- 现象：容易出现文本重复，几乎不会产生新颖表达。

6. **Top‑p=0.8（核采样）**

- 行为：动态保留累计概率达到0.8的候选token集合，动态截断候选池。
- 现象：兼顾正确性与适度多样性。

7. **Top‑p=0.5（严格截断）**

- 行为：候选集合被严格缩小，仅保留概率最高的一小部分token。
- 现象：生成多样性明显下降，容易出现重复文本。

8. **Top‑K=30**

- 行为：固定保留概率排名前30的token作为候选。
- 现象：候选池较大，会引入少量噪声，个别输出出现多余字符。

9. **Top‑K=10**

- 行为：缩小候选池，仅保留概率前10的token。
- 现象：噪声减少，但更容易出现输出重复。

> **小结**：情感分类、信息抽取这类确定性任务优先选择贪婪搜索或者低温采样；创意写作任务可以适度调高温度；温度过高会显著增加幻觉与错误率。`top‑p`、`top‑k`用于约束候选token集合，控制生成多样性。



## 3.4.2 选择一个具体任务，设计并对比以下不同的提示策略（如Zero‑shot、Few‑shot、Chain‑of‑Thought）对输出结果的效果差异

**问题：选择一个具体任务（如文本分类、信息抽取、代码生成等），设计并对比以下不同的提示策略（如Zero‑shot、Few‑shot、Chain‑of‑Thought）对输出结果的效果差异。**

本次实验选取两项NLP任务：

1. **影评多标签分类**：从`[剧情,画面,配乐,演技,叙事]`选出影评对应的标签，支持多选。
2. **客服用户意图识别**：从`[咨询,投诉,建议,退款申请]`识别用户诉求意图。



### Zero‑shot（零样本提示）

- **特点**：仅下发任务指令，不提供任何示范样例。
- **输出现象**
  - Base基座模型：指令跟随能力弱，容易输出大量无关解释文本，输出格式容易错乱。
  - Chat对话模型：可以完成基础任务，但输出格式不稳定，易附带多余文字。



### Few‑shot（少样本提示）

- **特点**：提示词中提供若干组“输入文本→输出结果”示范样例。
- **输出现象**：输出格式规整稳定，会严格模仿示例输出格式；输入token数量增加；在分类、标签抽取任务中表现最优。



### Chain‑of‑Thought（思维链CoT）

- **特点**：引导模型分步推理，先输出思考过程，再给出最终答案。
- **输出现象**：具备完整推理步骤，可解释性强；输出token更多，生成耗时更长；适合复杂推理任务；简单标签任务会带来不必要的思考开销。

> **小结**：简单分类、抽取任务优先使用Few‑shot；复杂推理任务适合CoT；Zero‑shot不需要样例，适合快速验证，但输出稳定性较差；Base基座模型整体指令跟随能力弱于Chat微调模型。



## 3.4.3 从性能、成本、可控性、隐私等维度比较闭源模型和开源模型

**问题：从性能、成本、可控性、隐私等维度比较闭源模型和开源模型。**


| 对比维度 | 闭源模型（GPT‑5、Gemini 2.5、Claude 4）                 | 开源模型（Llama 4、Mistral、Qwen3系列）                  |
| ---- | ----------------------------------------------- | ---------------------------------------------- |
| 性能   | 复杂推理、多模态、长上下文综合能力整体领先；能力受服务商版本限制，用户无法修改模型权重。    | 通用任务性能与闭源差距持续缩小；支持领域微调，垂直业务场景性能可超过闭源模型。        |
| 成本   | 按Token计费；硬件零投入，接入门槛低；大规模高频调用长期成本高，受服务商定价变动影响。   | 推理无Token计费；主要成本为GPU硬件、服务器运维；硬件一次性投入，后续推理边际成本低。 |
| 可控性  | 黑盒API调用，不能修改模型权重；仅能够调整temperature、top‑p等生成采样参数。 | 完全可控；支持量化、剪枝、LoRA微调；可以自定义安全策略、业务回答话术。          |
| 隐私   | 用户数据发送至第三方服务器；厂商“数据不参与训练”的承诺无法完整审计，存在泄露风险。      | 数据全部本地内网运行，不上传外部；适合医疗、金融、企业客服敏感数据，更容易满足监管合规。   |




## 3.4.4 如果你要构建一个企业级的客服智能体，你会选择哪种类型的模型？需要考虑哪些因素？

**问题：如果你要构建一个企业级的客服智能体，你会选择哪种类型的模型？需要考虑哪些因素？**

**选型：开源模型 + 本地私有化部署**

### 选型理由

1. **隐私合规优先**：企业客服对话包含大量客户个人信息、业务敏感数据；本地私有化部署保证数据不出企业内网，保护用户隐私，满足行业监管合规。
2. **长期成本优势**：硬件属于一次性投入，大规模并发对话推理不会产生按token计费的API费用，后期运维边际成本低。
3. **高度可控可定制**：可以基于企业客服业务语料、官方标准话术做LoRA微调，对齐企业回答风格；可自定义内容安全过滤策略。



### 需要综合考量的因素

1. **隐私合规约束**：客户对话数据是否允许流出企业内网，遵守行业监管条例。
2. **硬件资源条件**：服务器GPU显存、算力；评估量化压缩后的推理延迟，保障客服业务低响应时延。
3. **业务适配能力**：开源基座模型在意图识别、问答任务的基础能力，评估业务微调工作量。
4. **运维人力成本**：服务器运维、模型版本迭代、线上监控告警的人力开销。
5. **折中备选（混合部署）**：硬件资源不足时，敏感业务对话走本地开源模型；普通通用咨询调用闭源API。
