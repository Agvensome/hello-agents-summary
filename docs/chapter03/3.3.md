# 3.3 文本子词分词算法是大语言模型的一项关键技术，负责将文本转换为模型可处理的 token 序列。那为什么不能直接以"字符"或"单词"作为模型的输入单元？BPE（Byte Pair Encoding）算法解决了什么问题？

## 不能直接以单词作为输入单元
1. **词表爆炸问题**：自然语言存在海量词汇，还有大量衍生词、网络新词、专有名词。若把全部单词作为独立token，词表规模会无比庞大，带来巨大的存储与模型参数量开销。
2. **严重的未登录词（OOV）问题**：训练语料中没有出现过的词语，模型无法识别，只能标记为未知token，丢失语义信息。

## 不能直接以字符作为输入单元
1. **输入序列会变得非常长**：一句话被切分成大量字符，token数量大幅增加。Transformer自注意力复杂度是序列长度的平方，会带来极高的算力消耗。
2. **学习效率低下**：绝大多数单个字符不具备完整独立语义，模型需要额外学习字符如何组合成词语，大大增加模型的学习负担。

## BPE（Byte Pair Encoding，字节对编码）算法解决的问题
BPE的核心逻辑：先以字符作为初始词表，迭代合并训练语料中出现频率最高的相邻token对，不断扩充词表，最终得到子词词表。

1. **缓解未登录词（OOV）**：遇到训练集没见过的新词，可拆解成多个已有的子词单元，模型依然可以理解，不会直接出现未知token。
2. **平衡词表大小与序列长度**：高频词语保留完整单词作为token；低频、罕见词语拆分为子词。既避免纯单词方案的词表爆炸，又避免纯字符方案序列过长。
3. **保留形态学特征，提升泛化能力**：可以学习词缀、词根的组合，例如 `unhappy` 拆分为 `un` + `happy`，模型能够学到词缀语义，更好处理衍生、变形词汇。
