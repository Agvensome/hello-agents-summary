# 2.7 假设你要设计一个"智能代码审查助手"，它能够自动审查代码提交（Pull Request），概括代码的实现逻辑、检查代码质量、发现潜在BUG、提出改进建议。

## 2.7.1 如果在符号主义时代（1980年代）设计这个系统，你会如何实现？会遇到什么困难？

**实现方法：**
构建基于规则的专家系统。首先收集编程语言语法规范、常见Bug模式、代码最佳实践，人工编写大量`if‑then`产生式规则。对输入代码做语法解析，生成抽象语法树（AST）符号结构；通过规则引擎对语法树进行模式匹配，命中规则后输出对应的问题告警与修改建议。

**主要困难：**

1. **知识获取与维护成本极高**：每一类Bug、编码规范都需要工程师手动编写规则；当编程语言、框架更新，需要大量新增、修改规则。
2. **只能识别语法表层模式，无法理解业务语义**：可以捕获语法错误，但很难读懂代码背后业务逻辑，不能理解整个Pull Request的设计意图。
3. **泛化能力差**：代码只要做等价改写，即便逻辑仍有缺陷，规则就无法识别。
4. **规则冲突问题**：规则数量庞大后，不同规则之间容易发生冲突，系统调试维护难度急剧上升。

## 2.7.2 如果在没有大语言模型的深度学习时代（2015年左右），你会如何实现？

**实现思路：**

1. 将源代码解析为代码序列或者抽象语法树AST作为模型输入；
2. 收集大规模标注数据集：代码片段/Pull Request，附带人工标注的Bug位置、缺陷类型、质量问题标签；
3. 使用RNN/CNN等深度学习模型完成缺陷分类、缺陷位置定位任务；
4. 配合传统静态代码分析工具共同输出结果。

**局限：**
高度依赖高质量人工标注数据；模型只能识别训练数据中见过的缺陷模式；长程上下文理解能力弱，难以读懂完整PR的整体业务逻辑；很难直接生成流畅自然的改进建议，大多只能完成检测，无法输出完整的审查报告。

## 2.7.3 在当前的大语言模型和智能体的时代，你会如何设计这个智能体的架构？它应该包含哪些模块（参考图2.10 LLM驱动智能体架构）

采用**感知‑思考‑行动‑观察反馈循环**，各个模块分工：

1. **感知模块（Perception）**

接收外部输入，拉取Pull Request变更Diff、提交注释、项目文档，接收代码仓库的Webhook触发信号。

1. **思考层**

- **规划模块（Planning）**：把复杂审查任务拆解子步骤：①概括PR实现逻辑；②检查代码质量；③查找潜在Bug；④生成改进建议；完成后还可以对审查结果做反思校验。
- **大语言模型LLM（核心）**：负责代码语义理解、逻辑推理，综合信息生成审查意见。
- **记忆模块（Memory）**：短期记忆保存本次PR全部代码上下文；长期记忆存储项目专属编码规范、历史审查记录、项目高频Bug、业务约束。

1. **行动层**

- **执行模块（Execution）**：解析LLM输出的工具调用指令，调度工具箱，处理工具返回结果。
- **工具箱（Tool Use）**：调用传统静态检查Linter、Git API、文档检索工具、单元测试执行器，获取编译、测试结果，弥补大模型能力短板。

**完整工作流程**：感知获取PR代码变更 → 规划模块拆分审查子任务 → LLM结合记忆进行推理 → 调用工具箱获取静态分析、测试信息 → 汇总全部信息输出完整代码审查报告，结果可以反馈回感知模块迭代修正。

## 2.7.4 对比这三个时代的方案，说明智能体技术的演进如何使这个任务从"几乎不可能"变为"可行"

1. **符号主义时代（20世纪80年代）：几乎无法完成完整PR审查**

仅能实现简单语法检查。完全依赖人工编写规则，无法理解高层业务逻辑；面对真实项目中多样的代码写法泛化极差；维护海量规则成本不可承受，只能做局部浅层检查，做不到完整PR逻辑概括、Bug挖掘与建议生成。

1. **深度学习时代 (2015年)：可以做局部辅助，但无法独立完成完整任务**

可以学习识别训练集中的部分缺陷，但严重依赖大量标注数据；模型缺少长距离语义理解，很难把握整个PR的业务意图；不擅长生成自然语言分析建议。只能作为辅助工具，无法独立完成完整的智能代码审查。

1. **大模型智能体时代：任务具备可行性**

- 大模型具备强大代码理解、长上下文语义能力，可以读懂完整PR改动，理解业务逻辑，不再局限于固定模式；
- **记忆模块**可以保存项目特有的规范，适配不同项目；
- **规划模块**能把复杂的审查任务拆解成多步子任务，分步处理；
- **工具调用**可结合传统静态分析工具，将传统工具确定性能力和大模型语义推理能力互补；
- 不需要海量任务标注，依靠提示就可以完成复杂分析。

> 演进本质：从**人工硬编码规则** → **专用深度学习模型（依赖大量标注）** → **通用大模型+智能体架构（规划、记忆、工具）**。依靠智能体各组件的协同，把过去几乎不可能完成的完整PR智能审查任务变为现实。
